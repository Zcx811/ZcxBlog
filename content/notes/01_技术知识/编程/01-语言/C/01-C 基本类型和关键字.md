## 整型、浮点型、字符型

> 类型类结构。

### 是什么

整型用于表示整数，浮点型用于表示带小数或近似实数的数值，字符型用于表示字符或小整数值。

### 能表示什么

- 整型：计数、下标、状态值、位标志等整数信息。
- 浮点型：比例、坐标、测量值等允许近似表示的小数。
- 字符型：字符编码，也常用于表示字节数据。

### 存储 / 范围 / 特点

不同基本类型占用的字节数和范围与平台、编译器和数据模型有关。C 标准规定了基本关系和最低范围，但不要在所有平台上硬背固定大小。

### 类型转换规则

不同类型参与运算时可能发生隐式转换。例如整数和浮点数一起运算时，整数通常会转换为浮点类型；小范围类型也可能先提升为 `int` 参与计算。

### 怎么选择

- 需要表达整数计数时选整型。
- 需要小数和近似计算时选浮点型。
- 需要字符或字节数据时选 `char` 或相关字符类型。
- 涉及跨平台接口时，应优先明确类型宽度或使用项目约定类型。

### 最小示例

```c
int count = 10;
float score = 95.5f;
double pi = 3.1415926;
char ch = 'A';
```

### 易错点

- 把 `char` 只理解成字符，而忽略它也是整数类型。
- 默认认为 `int`、`long` 在所有平台大小固定。
- 用浮点数做精确相等比较。
- 在跨平台二进制接口中忽略类型大小差异。

### 面试问答

1. C 语言中常见的整型、浮点型、字符型分别用来表示什么？

答：整型表示整数，浮点型表示小数或近似实数，字符型表示字符编码，也可以看作一种小整数类型。

2. `char` 为什么既可以表示字符，也常被说成整数类型？

答：因为字符在内存中本质上也是编码值，`char` 存储的是字符编码对应的整数，所以它既能表示字符，也能参与整数运算。

3. `float` 和 `double` 在使用上通常有什么区别？

答：二者都是浮点类型，`double` 通常范围更大、精度更高；`float` 占用通常更小，但精度较低，适合对空间更敏感的场景。

4. 为什么不应该在所有平台上硬背某个基本类型的固定大小？

答：因为 C 标准没有要求所有基本类型在所有平台上大小完全相同，实际大小会受平台、编译器和数据模型影响，跨平台代码应使用 `sizeof` 或固定宽度类型确认。

## `signed`、`unsigned`

> 类型类结构。

### 是什么

`signed` 表示有符号整数类型，可以表示负数、零和正数；`unsigned` 表示无符号整数类型，只表示零和正数。

### 能表示什么

在相同位数下，`signed` 把一部分范围用于负数，`unsigned` 把所有范围用于非负数，因此 `unsigned` 的非负上限通常更大。

### 存储 / 范围 / 特点

`signed` 和 `unsigned` 的核心差异在于解释二进制位的方式不同。无符号类型没有负数概念，有符号类型需要表达正负。

### 类型转换规则

当有符号和无符号类型混合运算或比较时，可能发生隐式转换。有符号负数可能被转换成很大的无符号值，导致比较结果反直觉。

### 怎么选择

- 确定数据永远不为负，并且需要表达更大非负范围时，可以考虑 `unsigned`。
- 涉及差值、错误码、可能为负的值时，不应使用 `unsigned`。
- 与有符号类型混合比较时要谨慎。

### 最小示例

```c
int a = -1;
unsigned int b = 1;

if (a < b) {
    /* 这里的结果可能不是按“负数小于正数”的直觉理解 */
}
```

### 易错点

- 认为 `unsigned` 只是“不能为负”，忽略混合运算转换风险。
- 用 `unsigned` 表示循环下标时发生下溢。
- 把负数和无符号数直接比较。

### 面试问答

1. `signed` 和 `unsigned` 的核心区别是什么？

答：`signed` 可以表示负数和正数，`unsigned` 只表示非负数；同样位数下，它们对二进制位的解释和可表示范围不同。

2. 为什么 `signed` 和 `unsigned` 混合运算可能产生反直觉结果？

答：因为混合运算时会发生隐式类型转换，负的有符号数可能被转换为很大的无符号数，导致比较或运算结果不符合直觉。

3. 一个负数和 `unsigned int` 比较时，可能发生什么类型转换？

答：负数可能先被转换成 `unsigned int`，其二进制表示会按无符号数解释，结果可能变成很大的正数。

4. 实际开发中什么时候适合使用 `unsigned`，什么时候要谨慎？

答：明确只表达非负范围且不会参与复杂混合比较时可以使用；如果涉及差值、错误码、递减循环或与 `int` 混合比较，就要谨慎。

## 类型转换和溢出

> 概念 / 机制类结构。

### 一句话理解

类型转换是把一个类型的值按另一个类型解释或表示；溢出是计算结果超出目标类型可表示范围。

### 是什么

类型转换分为隐式转换和显式转换。隐式转换由编译器根据表达式规则自动完成，显式转换由程序员写出强制转换。

### 为什么需要

C 允许不同类型一起运算，也允许程序员接近底层地控制数据表示，因此需要类型转换。但转换也会带来精度丢失、符号变化和范围溢出风险。

### 怎么工作

表达式计算时，较小整数类型可能先提升为 `int`；整数和浮点数混合时，整数可能转换为浮点数；有符号和无符号混合时，可能转换为无符号类型。

### 怎么使用

- 尽量避免不必要的隐式转换。
- 对可能丢失信息的转换显式写出，并确认范围。
- 对外部输入、数组下标、内存大小等场景特别注意溢出。

### 最小示例

```c
double x = 3.14;
int y = (int)x;  // y 为 3，小数部分被丢弃

unsigned int u = (unsigned int)-1;
```

### 易错点 / 易混淆点

- 浮点转整数会丢失小数部分。
- 大范围类型转小范围类型可能截断。
- 有符号和无符号混用会改变比较语义。
- 溢出和精度误差不是同一个问题。

### 面试问答

1. 什么是隐式类型转换？什么是显式类型转换？

答：隐式类型转换是编译器根据表达式规则自动完成的转换；显式类型转换是程序员用强制转换语法明确写出的转换。

2. 浮点数转换成整数时，可能丢失什么信息？

答：通常会丢失小数部分，也可能因为目标整数类型范围不足而产生异常结果。

3. 什么是整型溢出？为什么它危险？

答：整型溢出是计算结果超过该整数类型能表示的范围。它危险是因为结果可能不是预期值，进而影响数组下标、内存大小、循环条件等逻辑。

4. `signed` / `unsigned` 混合运算和类型转换有什么关系？

答：二者混合时会触发整数转换规则，有符号值可能被转换为无符号值，负数会按无符号解释，导致比较和计算结果反直觉。

## `const`

> 语言规则 / 关键字类结构。

### 一句话理解

`const` 表示不能通过当前名字修改对象，用来表达只读意图。

### 基本含义

`const` 修饰变量、指针或函数参数时，限制通过该名字进行写操作，帮助编译器发现误修改。

### 核心规则

判断 `const` 和指针结合时，要分清限制的是指针指向的内容，还是指针变量本身。

### 不同位置 / 写法下的行为

- ==`const int *p`：不能通过 `p` 修改 `*p`。==
- ==`int *const p`：`p` 这个指针变量本身不能改指向。==
- ==`const int *const p`：既不能通过 `p` 修改内容，也不能修改 `p` 的指向。==

### 怎么使用

- 修饰不会被修改的局部变量。
- 修饰只读函数参数。
- 修饰指针接口，表达函数不会修改传入数据。

### 最小示例

```c
int x = 10;
const int *p1 = &x;
int *const p2 = &x;
```

### 常见坑

- 把 `const int *p` 误认为指针本身不能变。
- 把 `int *const p` 误认为指向内容不能变。
- 认为 `const` 一定等价于编译期常量。

### 易混淆概念

- 指向常量的指针。
- 常量指针。
- 宏常量。
- 枚举常量。

### 面试问答

1. `const int *p` 和 `int *const p` 有什么区别？

答：`const int *p` 限制的是 `*p`，不能通过 `p` 修改指向的值；`int *const p` 限制的是 `p` 本身，不能让 `p` 再指向别处。

2. `const` 修饰变量时，限制的是变量本身还是通过该名字进行修改？

答：核心是限制通过这个名字进行修改。对于普通对象表现为变量不可改；对于指针要看 `const` 修饰的是指针本身还是指向内容。

3. `const` 一定等价于编译期常量吗？

答：不一定。`const` 主要表达只读约束，是否能作为编译期常量还和语言规则、作用域、初始化方式等有关。

4. 函数参数中使用 `const` 有什么意义？

答：它表达函数不会修改参数指向的数据，能保护调用者的数据，也让接口语义更清晰。

## `static`

> 语言规则 / 关键字类结构。

### 一句话理解

`static` 在 C 中根据位置不同，可能表示静态存储期，也可能表示文件内部链接。

### 基本含义

函数内的 `static` 局部变量生命周期延长到程序结束；文件作用域的 `static` 变量或函数只在当前源文件内部可见。

### 核心规则

`static` 的含义取决于出现位置：局部位置主要影响生命周期，文件作用域主要影响链接属性。

### 不同位置 / 写法下的行为

- 局部变量前：作用域仍在函数内，生命周期持续到程序结束。
- 全局变量前：限制为当前源文件可见。
- ==函数前：限制该函数只在当前源文件内部调用。==
	## static 全局变量

```
static int g_count = 0;
```

#### 核心特点

- **生命周期**：贯穿整个程序运行期。
- **作用域**：文件作用域。
- **链接属性**：内部链接（internal linkage）。
- **跨文件访问**：不能直接被其他 `.cpp` 文件访问。

#### 示例

```
// a.cpp
static int g_count = 0;
```

```
// b.cpp
extern int g_count;   // 错误：无法链接到 a.cpp 中的 static g_count
```

不同 `.cpp` 中可以定义同名 `static` 全局变量，它们彼此独立：

```
// a.cpp
static int value = 1;

// b.cpp
static int value = 2;
```

#### 如果需要跨文件共享

```
// globals.h
extern int g_count;
```

```
// globals.cpp
int g_count = 0;
```

#### 一句话记忆

**static 全局变量：生命周期贯穿整个程序，但只能在当前翻译单元内访问。**

### 怎么使用

- 用局部 `static` 保存函数调用之间需要保留的状态。
- 用文件作用域 `static` 隐藏模块内部变量和辅助函数。

### 最小示例

```c
void count(void) {
    static int n = 0;
    n++;
}

static void helper(void) {
}
```

### 常见坑

- 以为局部 `static` 的作用域也变成全局。
- 忽略局部 `static` 在多次函数调用之间共享同一份状态。
- 忘记文件作用域 `static` 会限制跨文件访问。

### 易混淆概念

- 作用域。
- 生命周期。
- 链接属性。
- C++ 类静态成员。

### 面试问答

1. `static` 修饰局部变量时，作用域和生命周期分别是什么？

答：作用域仍在当前函数或代码块内，但生命周期延长到程序结束，函数多次调用会访问同一个静态局部变量。

2. `static` 修饰全局变量或函数时，会影响什么？

答：会影响链接属性，使该变量或函数只在当前源文件内部可见，不能作为外部符号被其他源文件直接引用。

3. C 语言中的 `static` 和 C++ 类中的 `static` 是否是一回事？

答：不是完全一回事。C 中主要讨论静态存储期和内部链接；C++ 类中的 `static` 成员还涉及类作用域和所有对象共享成员。

4. 为什么文件作用域的 `static` 常用于隐藏内部实现？

答：因为它把变量或函数限制在当前源文件内部，减少外部依赖和命名冲突，相当于模块内部私有实现。

## `extern`

> 语言规则 / 关键字类结构。

### 一句话理解

`extern` 用来声明一个名字在别处定义，常用于跨源文件引用全局变量或函数。

### 基本含义

`extern` 告诉编译器当前文件会使用某个外部定义的符号，真正的定义需要在链接阶段找到。

### 核心规则

`extern` 通常是声明，不分配存储空间；程序中仍需要且通常只能有一个对应定义。

### 不同位置 / 写法下的行为

- `extern int x;`：声明变量 `x` 在别处定义。
- 函数声明默认具有外部链接，很多情况下不需要显式写 `extern`。
- 如果变量被文件作用域 `static` 修饰，通常不能被其他文件通过 `extern` 访问。

### 怎么使用

通常把 `extern` 声明放在头文件中，把全局变量定义放在某一个 `.c` 文件中。

### 最小示例

```c
/* a.c */
int g_value = 10;

/* a.h */
extern int g_value;
```

### 常见坑

- 在头文件中直接定义全局变量，导致多重定义。
- 只有 `extern` 声明，没有任何 `.c` 文件提供定义。
- 误以为可以 `extern` 引用文件内部 `static` 变量。

### 易混淆概念

- 声明和定义。
- 外部链接和内部链接。
- `static` 文件作用域。

### 面试问答

1. `extern int x;` 通常是声明还是定义？

答：通常是声明，表示 `x` 的定义在别处，当前文件只是引用它。

2. 只有 `extern` 声明但没有实际定义，可能在哪个阶段出错？

答：通常在链接阶段出错，因为链接器找不到对应的外部定义。

3. `extern` 和文件作用域 `static` 在跨文件可见性上有什么区别？

答：`extern` 用于引用外部可见的符号；文件作用域 `static` 会把符号限制在当前源文件内部，其他文件不能正常 `extern` 引用。

4. 为什么全局变量通常不建议随意用 `extern` 暴露？

答：因为会增加模块耦合和全局状态依赖，容易导致维护困难、命名冲突和不可控修改。

## `typedef`

> 语言规则 / 关键字类结构。
> 本节已拆分为独立知识卡片：相关笔记。

### 核心结论

`typedef` 用来给已有类型起别名，不创建新的独立类型。它适合简化复杂声明，尤其是结构体类型、指针类型和函数指针类型。

### 与本主题的关系

- 与基本类型相关：可以给 `unsigned int`、平台相关整数类型等起更稳定的别名。
- 与指针声明相关：`typedef int* P;` 中 `P a, b;` 的 `a` 和 `b` 都是 `int *`。
- 与函数指针相关：可以显著降低函数指针声明和回调接口的阅读成本。

## `sizeof`

> 语言规则 / 关键字类结构。

### 一句话理解

`sizeof` 用来获取类型或对象占用的字节数。

### 基本含义

`sizeof` 是 C 语言中的运算符，不是普通函数。它的结果类型是 `size_t`，单位是字节。

### 核心规则

`sizeof` 可以作用于类型或表达式。对数组对象使用时得到整个数组大小，但数组作为函数参数后通常已经退化为指针。

### 不同位置 / 写法下的行为

- `sizeof(int)`：获取类型大小。
- `sizeof x`：获取表达式或对象大小。
- `sizeof(arr)`：如果 `arr` 是当前作用域数组对象，得到整个数组大小。
- 函数参数中的 `arr` 通常是指针，不再是完整数组。

### 怎么使用

常用于计算数组元素个数、内存分配大小、结构体大小和跨平台类型大小。

### 最小示例

```c
int arr[10];
size_t n = sizeof(arr) / sizeof(arr[0]);
```

### 常见坑

- 把 `sizeof` 当成函数。
- 在函数参数中用 `sizeof(arr)` 试图得到数组总大小。
- 忽略 `sizeof` 的单位是字节，不是元素个数。

### 易混淆概念

- 数组对象。
- 指针。
- 数组退化。
- `strlen`。

### 面试问答

1. `sizeof` 得到的单位是什么？

答：单位是字节，结果类型通常是 `size_t`。

2. `sizeof(type)` 和 `sizeof expression` 在写法上有什么区别？

答：类型名必须写在括号中，例如 `sizeof(int)`；表达式通常可以写成 `sizeof x`，也可以加括号。

3. 为什么数组作为函数参数后，`sizeof(arr)` 通常得不到整个数组大小？

答：因为数组作为函数参数时会退化为指针，函数内部的 `arr` 实际按指针处理，所以 `sizeof(arr)` 得到的是指针大小。

4. 如何用 `sizeof` 计算当前作用域内数组的元素个数？

答：使用 `sizeof(arr) / sizeof(arr[0])`，前提是 `arr` 仍然是当前作用域中的真实数组对象，而不是函数参数中的指针。

## `volatile`

> 语言规则 / 关键字类结构。

### 一句话理解

`volatile` 告诉编译器某个对象可能被当前程序控制流之外的因素改变，不要过度优化对它的访问。

### 基本含义

被 `volatile` 修饰的对象，每次访问都应按实际读写处理，不能简单假设它的值不会变化。

### 核心规则

`volatile` 约束的是编译器优化，不提供互斥、原子性或线程同步保证。

### 不同位置 / 写法下的行为

`volatile` 可以修饰普通对象，也可以和指针结合，表示指向的对象或指针本身具有 volatile 属性。

### 怎么使用

常见于内存映射寄存器、信号处理相关变量、底层轮询标志等可能被外部因素改变的场景。

### 最小示例

```c
volatile int flag;

while (!flag) {
    /* 等待外部修改 flag */
}
```

### 常见坑

- 认为 `volatile` 能保证线程安全。
- 认为 `volatile` 能替代锁或原子操作。
- 把编译器优化可见性和多线程同步混为一谈。

### 易混淆概念

- 原子操作。
- 互斥锁。
- 内存可见性。
- 编译器优化。

### 面试问答

1. `volatile` 主要是告诉编译器什么？

答：告诉编译器这个对象可能被当前代码之外的因素改变，因此不要把对它的读写访问过度优化掉。

2. `volatile` 能不能保证线程安全？

答：不能。它只约束编译器优化，不保证互斥、原子性或线程间同步。

3. `volatile` 能不能替代锁或原子操作？

答：不能。锁和原子操作解决同步和并发安全问题，`volatile` 不能保证复合操作的原子性。

4. 哪些场景中可能会看到 `volatile`？

答：常见于硬件寄存器、内存映射 IO、信号处理变量或底层轮询标志等场景。
